# Frontend

실제 `package.json`, lockfile, lint와 formatter 설정을 우선한다.
팀 합의 없이 프레임워크, 상태 관리, UI 라이브러리를 교체하지 않는다.

## 책임

- page/route: 화면 조합과 사용자 흐름
- component: 표현과 재사용 UI
- API client: 통신과 인증 처리
- server state: 서버 데이터와 캐시
- UI state: 모달, 선택, 입력 등 화면 상태

거대한 컴포넌트에 조회, 실시간 연결, 상태 전이, 표현을 모두 넣지 않는다.

## 비동기 UI

loading, success, empty, error, forbidden, disconnected/reconnecting을 처리한다.
입찰·낙찰·마감은 서버 성공 전에 확정 표시하지 않는다.
중복 실행 위험이 있는 버튼은 요청 중 다시 실행되지 않게 한다.

## 실시간

- 구독 시작·종료와 listener/timer 정리를 명확히 한다.
- 렌더링마다 중복 구독하지 않는다.
- 중복·오래된 이벤트가 최신 상태를 덮지 않게 한다.
- 클라이언트 timer로 경매 종료를 확정하지 않는다.
- 연결 장애와 재시도 상태를 사용자에게 표현한다.

## API와 보안

- URL, token, 환경값을 하드코딩하지 않는다.
- 공용 API client와 타입을 재사용한다.
- 프론트 권한 제어만으로 보안을 보장하지 않는다.
- 인증 만료와 권한 실패를 구분한다.
- 에러를 console 출력이나 빈 화면으로만 처리하지 않는다.

## 접근성

- 키보드 조작, focus, label을 지원한다.
- 색상만으로 상태를 구분하지 않는다.
- 오류는 관련 필드 가까이에 표시한다.
- 모바일과 QR 진입 흐름을 검증한다.

## 테스트

비로그인 진입·로그인 복귀, 주요 UI 상태, 입찰 중복 방지, 실시간 중복 이벤트,
재연결 보정, 서버 시간, 권한 실패, 폼 Validation과 접근성을 우선 검증한다.
